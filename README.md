# Peach Roadmap

Development plans and delivery progress for Peach.

[Board](https://github.com/orgs/peach-mitao/projects/7/views/1) · [Roadmap](https://github.com/orgs/peach-mitao/projects/7/views/3) · [Tasks](https://github.com/peach-mitao/peach-roadmap/issues) · [简体中文](README.zh-CN.md)

## Planning

- **One board**: application feedback and maintainer tasks share the same public project.
- **Priority**: P0 is urgent, P1 high, P2 normal and P3 low.
- **Stage**: near-term, later and exploratory plans indicate intent, not delivery dates.

[Report bugs or suggest features](https://github.com/peach-mitao/peach/issues/new/choose) in the application repository. Personal library, account and device work stays in private lists.

## Delivery

Implementation and pull requests belong in [Peach](https://github.com/peach-mitao/peach). Link a task from the PR body, for example: `Refs peach-mitao/peach-roadmap#1`. Full Issue URLs and GitHub's issue links are also supported.

A merged task enters verification. Record the release version when a downloadable package actually includes the change, then close the Issue after acceptance. Repository events and a check every six hours synchronize the board; board credentials are not stored here.

See the [board rules](https://github.com/peach-mitao/peach/blob/master/docs/PROJECT_BOARD.md) for synchronization details, and each Issue for its scope and acceptance criteria.
